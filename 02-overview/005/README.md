# תרגיל 005 — טופולוגיה סופית: EC2 + Load Balancer + RDS

## מטרה
לחבר את כל מה שלמדתם בתרגילים 001-004 לכדי ארכיטקטורה אחת שלמה:

```
אינטרנט
   ↓
Load Balancer (alb_sg: 80 פתוח לכולם)
   ↓
EC2 Instance (instance_sg: 8080 רק מה-ALB)
   ↓
RDS Database (db_sg: 5432 רק מה-EC2)
```

שימו לב ל-**שרשרת ה-Security Groups**: כל שכבה פתוחה רק לשכבה שמעליה, אף אחת לא חשופה ישירות לאינטרנט חוץ מה-ALB. זה עקרון ה-**defense in depth** שדיברנו עליו ב-03-basics.

## מה חדש כאן לעומת 003+004 בנפרד
שום משאב חדש מבחינת תחביר — זה בדיוק אותם `aws_lb`, `aws_lb_target_group`, `aws_db_instance` וכו' שכבר הכרתם. החידוש הוא **בחיווט ביניהם**:
- `aws_security_group.db_sg` מצביע חזרה על `aws_security_group.instance_sg.id` (לא על CIDR!) — כך רק תעבורה שמקורה ב-EC2 instance הספציפי הזה יכולה להגיע ל-DB

## המשימה
1. `terraform init && terraform apply -var="db_pass=<סיסמה-חזקה>"`
2. ⏱️ זה ייקח כ-5-10 דקות (בעיקר בגלל ה-RDS)
3. בדקו את ה-output `lb_dns_name` בדפדפן
4. **תרגיל מסכם**: נסו לדמיין (לא חובה להריץ בפועל) — איך הייתם מוסיפים שכבת S3 לאחסון קבצים סטטיים, בלי לפרוץ את העיקרון של "כל שכבה חשופה רק למה שמעליה"?

## ניקוי (סדר חשוב!)
```bash
terraform destroy
```
ל-Terraform יש גרף תלויות אוטומטי, אז זה ימחק בסדר הנכון (קודם ה-attachments/listener, אז ה-LB וה-RDS, ולבסוף ה-SGs) — אין צורך לדאוג לסדר ידנית כאן.
